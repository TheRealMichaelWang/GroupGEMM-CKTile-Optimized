# cktile_tunemax

Edit a CK Tile grouped GEMM, rebuild in ~20 s, and compare it against hipBLASLt on
Primus-Turbo's MoE grouped GEMM shapes. C++/HIP only, no Python at run time.

## Loop

```bash
# 1. edit ck_kernel/ck_grouped_gemm_config.hpp (tile sizes, pipeline...) or ck_grouped_gemm.cpp
./scripts/build.sh            # ~20 s CK-only rebuild; prints VGPRs/spills per CK kernel; checks CK headers
./scripts/run.sh top3         # 3 largest shapes, ~45 s
./scripts/run.sh full         # all 360 Primus-Turbo shapes
```

Useful flags (passed through to `build/tunemax_bench`):
`--dtype bf16|fp16` (default bf16), `--backends ck_tile` (skip baselines),
`--only 59,71` (TestIDs), `--warmup 20 --iters 100`, `--no-check`, `--out file.csv`.

Always look at the build output for `VGPRs Spill:`. Anything above 0 makes the kernel
many times slower (256x256 tiles spill ~400-700 with this compiler).

## Layout

| Path | What |
|---|---|
| `ck_kernel/` | **The kernel being tuned.** Config header + persistent `ck_tile::GroupedGemmKernel`, RCR layout, bf16/fp16, padded fallback when shapes aren't tile multiples. Its own static lib, so edits rebuild only this. |
| `backends/hipblaslt_grouped_backend.cpp` | `hipblaslt_ext::GroupedGemm`: one launch for all groups, device-side args, **default heuristic top-1** (no tuning). |
| `backends/hipblaslt_loop_backend.cpp` + `third_party/primus_turbo/` | Primus-Turbo's `hipblaslt_grouped_gemm.cu`, vendored unmodified (commit `8cda13c`): one `hipblasLtMatmul` per group over 4 streams. |
| `bench/bench_main.cpp` | Reads a shapes CSV, runs each backend, checks the output, times it, writes results. |
| `shapes/full.csv`, `shapes/top3.csv` | Same columns (`TestID,Case,B,M,N,K`). Generated by `scripts/gen_shapes.py` from Primus-Turbo's `benchmark/ops/training/config.py` (same cases and TestIDs as `bench_grouped_gemm_turbo.py`). top3 = most FLOPs. |
| `results/` | One CSV per run: `TestID,Case,B,M,N,K,Dtype,GPU,Backend,Check,Time_ms,TFLOPS,MaxAbsErr,Detail`. |

## What is measured

- Forward pass only: `out[g] = x[g] @ w[g]^T`, x `[B*M, K]`, w `[B, N, K]`, balanced groups
  (Primus's benchmark also times backward; not done here).
- Inputs ~N(0,1). Check: about 260 sampled outputs per group vs an fp32 GPU reference,
  tolerance rtol = atol = 1e-2 (same as Primus's `check_allclose`).
- Time: 20 warmup calls, then HIP events around 100 back-to-back calls on one stream →
  mean ms. Setup (argument buffers, heuristic query for the grouped backend) is untimed.
  The loop backend's per-call host work (arg setup + a heuristic query per group) is
  timed, because that is what Primus-Turbo pays.
- CK headers come from `/workspace/rocm-libraries/projects/composablekernel` (override:
  `CK_ROOT=... scripts/build.sh --clean`). `scripts/check_ck_headers.sh` fails the build
  if any `ck_tile` header came from `/opt/rocm`. hipBLASLt/hipBLAS come from `/opt/rocm`.

## Known facts (MI355X, ROCm 10.0)

- Installed hipBLASLt has grouped kernels for **fp16 only** on gfx950, so
  `hipblaslt_grouped` is N/A in bf16. Use `--dtype fp16` for the 3-way comparison.
  Its default heuristic picks a 16x16 tile for these shapes (~90 TFLOPS), which also makes
  fp16 runs slow (~4 min for top3). Use `--backends ck_tile,hipblaslt_loop` to skip it.
- Current best, top3 bf16: ck_tile ~1555 TFLOPS (1525-1575 per shape) vs hipblaslt_loop ~1427,
  both at the 1400 W power cap. Full suite (bf16, 360 cases, same GPU, `results/full_bf16_ck_gpu6.csv`
  vs `results/full_bf16_hipblaslt_loop.csv`): ck_tile faster in 337/360, geomean 1.69x (the loop's
  timed region includes a heuristic query per group, as in Primus-Turbo). The 23 losses are
  single-group shapes with < 256 tiles or 1.4-2 rounds of tiles (hipBLASLt's single-GEMM kernels
  use stream-K there), plus two within 1%. GPUs differ by ~2%: compare backends on the same GPU. Pipeline: `ck_kernel/hand_pipeline_asm_s.hpp` (HandPipelineAsmS:
  hand-scheduled 4-wave 256x256x64 main loop, inline-asm MFMAs, async global->LDS loads) inside
  `ck_tile::GroupedGemmKernel` (persistent), C stored by `ck_kernel/fast_epilogue.hpp`. CK itself
  is unmodified. Tuning history: `TUNING.md`; quick loop: `scripts/quick.sh`; per-tile cycle
  breakdown from a thread trace: `scripts/att.sh` (+ `scripts/att_rows.py`).
